## 固定 slot 画布与异步结果绘制（2026-10-30）

本节为当前绘制实现，替代前述将画框放入 200ms UI 状态线程的方式。

- 一个独立 `UI_Hdw24gDrawThread` 处理所有显示 slot；不新增四个绘制队列，不积压待绘旧结果。线程优先级 Normal、栈 4096 字节，初始化时仅创建一次。
- 新有效结果在 RX 收包线程校验并写入对应配对槽缓存后，以 `osSignalSet()` 唤醒绘制线程。重复载荷仅更新存活时间，不重复唤醒。线程用 `osSignalWait(0, 50)` 等待；50ms 只是无新结果时的过期/菜单/视图检查上限，收到信号立即继续，没有每帧固定 50ms 或 200ms 的延时。
- `tUI_Hdw24gCanvas[slot]` 固定绑定显示 slot，内部为局部坐标框/图标清单与已绘结果缓存。单画面 slot0 为 1024×600；双画面 slot0/1 各 512×600，屏幕偏移为 (0,0)/(512,0)；四分割 slot0～3 各 512×300，偏移为 (0,0)/(512,0)/(0,300)/(512,300)。尺寸仅在分屏布局改变时调整，CAM 替换不改变 slot 的位置或尺寸。
- 依据 `tCamViewSel.tCamViewPool[slot]` 将当前 CAM 映射到固定 slot，再通过原配对映射读取该 CAM 的无线缓存。只对结果内容、CAM 映射、类型过滤开关或 UI 覆盖状态发生变化的 slot 清旧框并重画。四路结果无需同时到达；未变化的 slot 保留之前的框和图标。每 slot 的目标上限分别为 20/10/5。
- 框和图标在画布内使用局部坐标，仅在写入/擦除共享 OSD2 时加 slot 偏移。框线避开中间 4 像素分割线。复用现有 OSD2，未增加整屏像素缓冲。SDK 最终仍使用原 OSD 提交接口，逻辑上只修改变化的 slot。
- 显示 CAM 按原配对映射转换为 STA 可见掩码；隐藏 CAM 的独立算法包在 RX 丢弃，不缓存、不唤醒绘制线程。可见掩码变化时清除受影响 CAM 的旧缓存；切回显示后等待新结果，避免复用隐藏前的旧框。无线发送协议不变。
- 某个 slot 的零目标、结果过期、CAM 断线/换 ID 或过滤关闭仅清该 slot。CAM 发生替换时先清此 slot 旧框，再取新 CAM 结果；不移动其他 slot。菜单清屏通过画布代次失效缓存，菜单中不绘制，退出后按最新结果恢复。
- 按原顺序获取 `osUI_UpdateStatusCtr`、`osUI_CuUiCtr`，底层沿用 `OSD_Mutex`。音量菜单直接入口补上 UI 信号量保护，避免与绘制线程交叉清屏。200ms UI 状态处理保留原状态/配置轮询，仅标记被 UI 图标覆盖的已绘 slot 需要修复并唤醒绘制线程。

验证：7/10 寸配置的 UI、菜单、RTC676x 三个 C 文件语法检查通过，无新增告警。使用实际画布、局部坐标变换、绘制/擦除、菜单清屏、RF 校验/缓存/通知及线程函数进行临时验证：固定 slot 尺寸与偏移、20/10/5 上限、四路错峰到达只更新对应 slot、未变化 slot 不清除、隐藏 CAM 丢弃、切回等待新结果、CAM 替换不改变 slot 几何、零目标/过期/断线/换 ID、重复包抑制、非阻塞收包锁、菜单清屏/暂停/退出恢复、线程锁顺序及像素缓冲边界。AddressSanitizer/UBSan 通过。当前环境无 Keil/ARMCC 和设备，实际 LCD 提交耗时及跟框帧率仍需真机测量。
